# Native LibreChat traceability matrix

**Prepared:** 2026-08-18  
**Purpose:** Keep product decisions, LibreChat protocol facts, implementation status, and acceptance evidence connected while the native app is built.

## Evidence rules

The competitor reports currently contain official-source research and design inferences, not direct visual audits. The required browser surface was unavailable, so this matrix must not be read as evidence of exact competitor spacing, hierarchy, hit targets, animations, VoiceOver semantics, or error-state presentation. Direct capture is still required before making visual claims. See the [ChatGPT audit](Audits/ChatGPT.md), [Claude audit](Audits/Claude.md), and [other-app scan](Audits/OtherMajorAIApps.md).

LibreChat references below are pinned to the deployment/source baseline documented in [SourceBaseline.md](LibreChatKnowledge/SourceBaseline.md): the detached source clone is `b2128a7d189ac020ebb6e49a57ee986e98326b77`. “Current iOS status” distinguishes app-wired code, fixture-tested behavior, and real-server proof; it is not a claim that the flow has passed real-server acceptance unless the row explicitly says so.

Priority means delivery order: **P0** protects correctness/trust of the existing core, **P1** completes the useful product loop, and **P2** adds breadth after core recovery and accessibility are proven.

Final verification passed **367 Swift Testing tests across 44 suites plus 4 XCTest checks (371 package checks)** at [`/private/tmp/librechat-skill-management-core`](/private/tmp/librechat-skill-management-core), with **126 newer app/model/repository tests compiling but not executing**, and generic physical-device and Simulator build-for-testing at [`/private/tmp/LibreChatIOS-SkillManagement-Device-Derived`](/private/tmp/LibreChatIOS-SkillManagement-Device-Derived) and [`/private/tmp/LibreChatIOS-SkillManagement-Simulator-Derived`](/private/tmp/LibreChatIOS-SkillManagement-Simulator-Derived). No Simulator was booted, no UI tests ran, and no live server call occurred for this verification. Use [LiveAcceptanceRunbook.md](LiveAcceptanceRunbook.md) for the remaining bounded evidence.

The Phase C queue has a no-repost reconciliation boundary: reserved, uncertain, committed, or admitted attempts can be recovered only when retained v2 status proves the exact stream, newer epoch, frozen user message ID, parent, text, queued server file-ID set, and empty unsupported rich-input fields. An already-admitted row must match its exact saved handle; retained terminal proof additionally requires authoritative durable message rows. AppModel invokes this before general generation discovery during session restoration, foreground, and connectivity recovery. Exact jobless user-plus-single-clean-assistant history closes the row without a synthetic handle and blocks followers that cannot receive a verified predecessor epoch. Each app-level recovery signal also refreshes the visible chat's queue and authoritative history before attempting stream recovery, including the no-active-generation branch.

The implemented recovery contract is deliberately narrow: cached nonterminal snapshots are reconciled under the active profile/account, `/api/agents/chat/active` IDs are deduplicated, and each ID must pass exact status proof for `streamId`, `createdAt`, and protocol `2` before installation. Sign-in/session restoration, foreground activation, and a genuine active-app offline→online transition start a cancellable recovery task; backgrounding and profile switches cancel it. Discovery persists snapshots but never opens a global SSE stream. On foreground, the currently visible chat may consume the reconciled signal once only after profile/account/conversation/exact-handle, operation-ownership, and sequence checks. It resumes an active stream automatically or reloads authoritative history without reopening SSE when the run became terminal. Connectivity recovery is stricter: it never adopts a newly discovered handle and may retry only the exact saved visible handle after the current operation stopped. Both retain manual Resume after a recoverable attach failure. Transport and `/active` 404/405 failures retain local checkpoints, while identity mismatches and unauthorized responses fail closed. Start recovery additionally uses typed `SERVER_NOT_READY`, the same request for up to 120 seconds, idempotent status retries, deterministic UUIDv5 new-chat identity, and exact inactive-history/message matching. An assistant response is attributed only through exact `responseMessageId`; an active ambiguous new-chat recovery must prove exact stream/conversation/epoch/protocol/status identity, while an existing-conversation active ambiguity fails closed. Malformed, unknown-status, and identity-mismatched start receipts are rejected; `aborted` and `error` remain terminal rather than being collapsed into completion.

The `LibreChatUITests` target historically executed fixture assertions for searchable New Chat target selection, saved-chat target-to-new-chat transition, dismissal/navigation, existing-row navigation, manual scroll/Jump to latest, exact message-search focus onto a nondefault branch, conversation-fork review, response-regeneration review, and the composer execution envelope and controls. Debug-only `-ui-test-fixtures` injects in-memory profile/cache/secret stores and an allowlisted URL protocol, with no Keychain or real network. App/model/repository tests executed 371/371 successfully and the historical UI target executed 7/7 successfully. Thirteen deterministic UI methods now compile: six newer methods are compile-only, including the artifact card-to-workspace-to-Back flow. No Simulator was booted for this update and no authenticated live network acceptance ran.

The predecessor handoff safety contract is now fixture-verified: an active v2 receipt/status must prove the exact stream, epoch, and protocol and use a different expected predecessor epoch. Losing optimistic rows are removed, unsent draft text is restored and persisted, and a verified terminal or superseded winner never opens SSE. A transient handoff failure leaves the visible manual Resume path; there is no automatic resend and no reuse of the losing client request ID. This remains build/fixture evidence only until a manually booted Simulator and authenticated deployment provide live proof.

The text-only prompt edit-and-resubmit branch is admission-gated to the selected persisted authoritative user prompt with one primary text slot. It keeps the original prompt and replies unchanged, sends ordinary generation under the exact original parent with stable validated caller IDs, excludes attachments/rich/artifact/citation content, requires verified resumable v2 and authoritative idle preflight, fences UI/model state, never blindly reposts ambiguity, never attributes a losing handoff, reloads/focuses accepted terminal history, and hides cached history on 401. This is distinct from save-only edit, response regeneration, Continue, assistant resubmit, and conversation fork.

Response regeneration is admission-gated to a selected persisted finished plain-text assistant that is the direct child of the exact user source. It verifies the authoritative branch and target fingerprint, v2 negotiation, idle status, and fresh policy/catalog evidence; sends exact source/override-parent/preliminary-response coordinates with stable request identity and bounded retries; replays persisted `manualSkills` only after exact source identity match and never drains a compose selection; preserves the original subtree while creating a new assistant sibling; excludes attachments, quotes, rich content, citations, and artifacts; shows the current target; never blindly reposts; proves exact new-sibling identity for settled/failed outcomes; never attributes a typed losing handoff; hides history on 401; and locks the one-shot sheet/review flow.

Local copy/share is a separate privacy-bounded presentation path. The domain formatter receives only the selected projected branch and emits a readable Markdown transcript with a single-line title, fixed role labels, and cleaned visible text. The native conversation menu passes that bounded string to the clipboard or system share sheet; per-message copy uses the same cleaned-text boundary. Neither path exports profile/account/message IDs, model or endpoint metadata, files, tool payloads, hidden siblings, or a round-trippable conversation archive. Core transcript tests execute, while the SwiftUI menu/share interaction remains compile-only.

Message feedback is a distinct persisted-response mutation. The native domain derives rating from LibreChat's closed reason registry, accepts only the exact selected finished assistant response, sends one non-retried PUT, and requires exact returned coordinates plus desired feedback. Transport/5xx/malformed-acknowledgement ambiguity is resolved by one authoritative history GET, never a second PUT; unresolved outcomes lock that exact response until refresh. The review sheet exposes set/edit/clear, the UTF-16 limit, server-observability disclosure, and confirmation-only accessibility announcements. Full package and app/model tests execute, but no authenticated request or accessibility run has occurred. Exact contract: [MessageFeedback.md](LibreChatKnowledge/MessageFeedback.md).

## Promotion gates

A capability can move from “fixture-tested” to “proven live” only when the exact server response/event contract, authenticated simulator flow, and recovery/accessibility behavior have evidence. A capability can move from “scaffold” or “partial/mismatched” to shippable only when:

1. its server route and payload are pinned to source or captured fixtures;
2. its repository/domain mapping is explicit and unknown fields remain safe;
3. its cache/profile/account behavior is tested;
4. its UI has loading, empty, offline, permission, and failure states;
5. its accessibility behavior is checked at large Dynamic Type and with VoiceOver; and
6. a real deployment run verifies the happy path and at least one interruption.

The absence of competitor screenshots is intentionally preserved as a limitation. Once a controllable browser/device session exists, add accepted captures under `Documentation/Audits/Assets/` and update only the competitor-evidence cells they directly support; do not backfill exact visual claims from memory or documentation pages.
