## How to read this audit

Classification is deliberately evidence-based:

- **Proven live**: an authenticated simulator/device flow has been exercised against a real deployment, including the relevant recovery behavior. There is no such evidence for generation in this audit.
- **Observed live smoke**: the user reported that password login reached a loaded conversation list on the pinned deployment. That is useful interoperability evidence, but there is no captured request/response, refresh-cookie rotation, repeatable run record, or post-fix interaction proof, so it does not promote either feature to “proven live.”
- **Built / app-wired**: the source path is reachable through the app and repository, but no dedicated fixture or real-server proof is recorded.
- **Implemented, fixture-tested**: code and tests cover the protocol/domain behavior, but there is no demonstrated end-to-end UI/server proof.
- **Partial/mismatched**: a real-looking path exists, but important routes, states, capabilities, or server contracts are incomplete or wrong.
- **Scaffold only**: types, mappers, reducers, or persistence shape an intended feature, without a user-completable product path.
- **Absent**: no native implementation was found.

The pinned server contract matters: `/api/config` and provider flags do not prove native OAuth; generation v2 must be negotiated per operation; browser refresh is cookie-backed; resources such as projects, agents, MCP, prompts, skills, and memories are permission-scoped.

## Executive conclusion

This is a credible native foundation for **server setup, local login/2FA challenge, profile/account isolation, cached conversation browsing, file staging/upload, and a generation-v2 state machine**. The foundation has unusually good domain modeling and fixture coverage for SSE ordering, cookie isolation, cache boundaries, and generation recovery.

It is not yet a complete LibreChat client. The visible product now includes capability-gated local-account registration and email-verification resend, Chats/Messages search, bounded Projects, ACL-filtered Agents with basic private creation, metadata edit, server-side duplicate, safe version history/revert, and ACL-proven deletion, a redacted read-only MCP connection catalog, live-only Memory management, a live ACL-filtered Prompt Library, owned prompt metadata/version management, a live owner Preset library with reviewed compatible New Chat application and bounded native creation, native Skills catalog/manual invocation/account activation, authenticated-owner sharing, an owner-reachable public snapshot, direct-path fork review/navigation, capability-gated native STT dictation, and explicit assistant-response Read Aloud with server-backed voice selection. Registration does not authenticate; browser-link verification/reset completion remains external. OAuth is only an optional extension probe and cannot work against the pinned server; empty-chat creation remains local until generation; automatic/streaming TTS, background/full-duplex voice, Skill authoring/files/import, durable pending-Skill queue persistence, advanced/full agent configuration/avatar/action/share management, assistants, MCP selection/tools/auth-values/management/OAuth, prompt deletion/labels/sharing/ACL administration, preset edit/default/import/export/delete and full parameter execution, branch-inclusive fork modes, external universal-link/standalone anonymous share entry, owner directory, and broader ACL/admin management remain missing or live-unproven. Many app tests are compile-only, and authenticated/live behavior remains unproven.
