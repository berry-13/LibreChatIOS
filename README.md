# LibreChat for iOS

A fully native SwiftUI client for self-hosted LibreChat. It targets iOS 17, compiles with Swift 6 complete concurrency checking, and progressively adopts iOS 26 Liquid Glass for application chrome.

The product direction is grounded in a screenshot-led visual audit of major native AI apps and a pinned LibreChat protocol knowledge base. The goal is a calm Apple-platform workspace that makes target, scope, provenance, human decisions, and recovery more legible than a generic chatbot or a compressed web dashboard.

## Architecture

`Packages/LibreChatCore` is the protocol boundary:

- `LibreChatDomain` contains stable IDs, models, repository protocols, compatibility types, and generation state.
- `LibreChatProtocol` contains permissive DTOs, explicit mappers, REST/SSE transports, a profile cookie jar, `AuthSession`, capability detection, generation decoding, and the generation reducer.
- `LibreChatTestSupport` contains fixtures and transport/storage doubles.
- `DesignKit` contains semantic SwiftUI components; glass is limited to controls and navigation chrome.

The application target owns feature models, SwiftData V1 cache records, the composition root, platform integrations, and adaptive navigation. Networking, authentication refresh, cookies, SSE framing, generation ordering, retries, and reconciliation do not live in SwiftUI models.

## Implemented flows

- Multiple profiles, including multiple accounts on the same host, with isolated runtime, Keychain-backed cookies, cache namespaces, and generation state.
- HTTPS enforcement for remote hosts and narrow loopback HTTP support for development.
- Capability discovery from startup configuration, bounded authenticated post-login refresh for shared-link policy, and optional mobile-auth discovery. Unknown generation support negotiates on first send; incompatible instances remain available for read-only browsing.
- New Chat consumes an account-scoped `TargetCatalogSnapshot` built from fresh authenticated `/api/config`, `/api/endpoints`, and `/api/models` plus agent ACL and non-secret user-key evidence. It enforces `modelSpecs.enforce`, `interface.modelSelect`, `addedEndpoints`, credential availability, saved-agent access, and the server's explicit/default ordering; a failed policy refresh exposes no stale choices, compatibility notices explain hidden targets, and a removed selected target requires an explicit new choice instead of silent replacement. Ordinary and project-scoped New Chat share a native searchable selector that groups configured specs, agents, and models without changing authoritative option order; search uses only user-facing metadata and never exposes raw agent IDs. From a saved chat, the composer can reopen that authoritative catalog and start a fresh local conversation with the chosen target while leaving the existing history/branch untouched and preserving project scope. This deliberately follows LibreChat's non-modular switch behavior; modular multi-conversation switching is not claimed. The last successful local-draft target becomes the next fresh catalog's default only when that exact option still exists. The preference is a trimmed 1...2,048 UTF-16-unit option ID stored under the existing `recent-chat-target-v1` configuration-payload kind and exact profile/account namespace, so it adds no SwiftData V1 column or migration; failed or canonical/server-side creation never writes it.
- A capability-gated native Agents library walks the ACL-filtered `GET /api/agents` cursor contract, searches server-side, and opens the view-safe `GET /api/agents/:id` surface. “Start chat” refreshes the authoritative target catalog and proceeds only for one exact permitted agent target. Fresh authenticated, online `AGENTS.USE + CREATE` proof unlocks bounded management and basic private creation: creation refreshes `/api/models`, exact-matches the reviewed provider/model, sends one strict allowlisted `POST /api/agents`, and accepts only a generated-ID/request-echo `201`; uncertainty gets one owner GET reconciliation and then a finite lock, never a repost. Metadata editing preflights `GET /api/agents/:id/expanded`, PATCHes only `name`, `description`, and `category`, then reconciles uncertain results with GET-only server truth; duplication uses the one-shot server-side `POST /api/agents/:id/duplicate` and locks on ambiguity. Version history reads the exact EDIT-gated raw array, preserves every original server index (including malformed placeholders), immediately projects only bounded safe metadata, and restores through a fresh-index-verified, never-retried `POST /api/agents/:id/revert`; any lost or malformed acknowledgement locks as outcome unknown. Deletion keeps the public agent ID distinct from Mongo `_id`, exposes its destructive action only after a live effective-permission DELETE bit, never retries the DELETE, and resolves ambiguity with one read-only existence check. The basic create contract excludes tools, actions, files, MCP, skills, subagents, credentials, avatar, and sharing/ACL configuration; expanded data never enters presentation or cache. A post-response 401 or browser redirect from any `.never` mutation is not automatically replayed, while GET/idempotent auth recovery remains available. Advanced/full authoring, avatar, actions/tools, and sharing/ACL administration remain separate, disabled contracts. See Saved-agent management.
- Native Skills now include bearer-authenticated paginated catalog, account active-state reads and one-shot whole-map writes, role plus agents-capability gates, account defaults, model-spec and saved-agent scope, truthful inactive/model-only/excluded states, duplicate-name quarantine, exact picker cancellation, max-10 fresh preflight, and `manualSkills` generation wiring. Settings exposes live-only account activation with serialized writes and one bounded GET reconciliation instead of blind repost. Regeneration replays persisted selections and the pending selection queue blocks until the reviewed target/catalog remains valid. Authoring/files/import, durable queue selection persistence, and authenticated live proof remain deferred; see Skills and manual invocation.
- A role-gated, read-only MCP Connections screen now combines the exact authenticated `GET /api/mcp/servers` and `GET /api/mcp/connection/status` contracts. It shows only redacted title/description, transport, management source, direct-vs-agent availability, connection state, and authorization state; it does not request or expose URLs, headers, custom variables, credentials, OAuth tokens, or tool payloads, and it stores no connection catalog offline. Unknown future states remain visible but never become authorized. Native connector selection, configuration, OAuth, and tool catalogs remain disabled until their account-bound security contracts are implemented and live-proven.
- A capability- and role-gated native Memory center now uses the exact authenticated `/api/memories` list/create/update/delete and preference routes. It preserves personal and agent-specific partitions without exposing raw agent IDs, enforces the server-provided UTF-16 character budget, shows token usage, never blindly retries mutations, and accepts only identity-matching acknowledgements. Memory values are intentionally live-only: they are not written to SwiftData, configuration snapshots, logs, or offline cache. Offline mode explains that private memory must be reloaded from the server; only the account's memory-enabled preference is retained with the verified user record. Authenticated runtime acceptance remains pending.
- A role- and ACL-gated native Prompt Library browses the live `GET /api/prompts/groups` cursor directory, expands reviewed variables locally, and appends without replacing or auto-sending. Settings now adds a separate live-only **My templates** manager for owned metadata, creation, version history, new versions, and explicit production promotion. Exact resource identity is verified; new versions never auto-promote; mutations never retry automatically; ambiguous create/add operations lock, while metadata/promotion reconcile through GET-only server truth. Prompt contents are not cached or logged. Delete, labels, sharing/ACL administration, and authenticated live acceptance remain pending; see Prompts and templates.
- A live-only native Preset library is gated by fresh authenticated `interface.presets` evidence and reads exact owner-scoped `GET /api/presets` only when enabled; offline, anonymous, malformed, or explicit-false policy hides it without traffic. Compatible presets remain server-ordered, searchable, reviewable, and create an unsent local chat without mutating history. Native creation is a separate reviewed write: it refetches the live target catalog, requires the exact profile/account and selected-target fingerprint still match, uses a caller-generated UUID, and sends only the safe routing/title/prompt fields in one non-retried `POST /api/presets`. A 201 response is success only when it exactly echoes the saved native-safe preset; an ambiguous post-dispatch result locks creation until one owner-list reconciliation. Default/edit/delete/import/export and full provider-parameter execution remain pending; see Presets and native application.
- Native Settings now manages account-scoped user-provided provider credentials from fresh authenticated endpoint policy and expiry-only `/api/keys` evidence. It reproduces LibreChat's exact simple/OpenAI/custom/Azure/Google/Bedrock envelopes, keeps secrets in transient secure editor state only, never caches or reads them back, and never blindly retries a save or revoke. Lost rotation responses remain explicitly uncertain; lost revocation is accepted only when status proves the key absent. Live disposable-key acceptance remains pending; see User-provided provider credentials.
- Native Settings now has a server-authoritative **Profile and account** surface. It refreshes the exact signed-in identity from `GET /api/user`, replaces PNG/JPEG avatars through the configured byte limit and one-shot multipart upload, and exposes self-deletion only from fresh authenticated `allowAccountDeletion` evidence. Destructive deletion requires explicit confirmation plus transient TOTP/backup proof when enabled; it is never retried automatically, and only the exact `User deleted` acknowledgement purges the account namespace and signs out. Name, username, email, and role remain read-only because the pinned server exposes no matching profile-edit route. Live acceptance remains pending; see Account profile, avatar, and self-deletion.
- A live-only Files library now browses exact authenticated `GET /api/files` from the account menu. ## Verification

Run package contract tests:

```sh
cd Packages/LibreChatCore
swift test
```

Run the application and SwiftData tests:

```sh
xcodebuild -project LibreChatIOS.xcodeproj \
  -scheme LibreChat \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  CODE_SIGNING_ALLOWED=NO test
```

## Rate limiting and IP bans

LibreChat's `api/server/middleware/uaParser.js` (mounted on the chat/files/agents routers) logs a `NON_BROWSER` violation for any User-Agent that ua-parser-js cannot parse as a browser. The default score is 20, equal to `BAN_INTERVAL`, so **one** request with a non-browser User-Agent causes an instant IP + account ban (`BAN_DURATION`, default 2 hours). URLSession's default UA (`AppName/1 CFNetwork/... Darwin/...`) triggers this.

- Every build configuration sends a Safari-profile User-Agent with a trailing `LibreChatiOS/1.0` identification token via `UserAgentPolicy` in `LibreChatProtocol/HTTP.swift` (applied to both the REST and SSE sessions). The browser-parseable prefix satisfies `uaParser`; the trailing token lets servers distinguish the native client in logs without breaking browser detection (ua-parser-js matches the unanchored `Version/… Mobile/… Safari/…` tokens first).

To clear an existing ban and its violation counters (otherwise the next threshold re-bans):

```sh
# MongoDB (default violation/ban store; database "LibreChat", collection "keyv")
mongosh LibreChat --eval 'db.keyv.deleteMany({ key: { $regex: /^(bans:|violations:)/ } })'

# Redis (when USE_REDIS=true)
redis-cli --scan --pattern 'ban_cache:*' | xargs redis-cli del
redis-cli --scan --pattern 'violations:*' | xargs redis-cli del
```

Other limits a mobile client can hit on a single shared egress IP: `LOGIN_MAX` (default 7 per 5 minutes) and `MESSAGE_IP_MAX` (default 40 per minute). The app already never auto-retries `POST /api/auth/login`, mutations, or 403/429 responses; only transport failures and `SERVER_NOT_READY` are retried.
